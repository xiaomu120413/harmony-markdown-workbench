# 木笺界面重设计 ST-DESIGN-001

REQ-DESIGN-001：重新设计现有首页、编辑器和设置页，让文档与正文成为主要内容，统一控件、留白、文字与浅深主题。沿用原生按钮、系统图标、键盘焦点和既有业务逻辑；不增加权限或业务抽象，手写文件不超过 500 行。

## 当前界面检查

2026-10-22 从 API 24 手机模拟器、API 26 PC 真机重新采集并打开截图，不以历史截图判断当前界面。

1. 首页：手机的大面积主色按钮压过文档列表；PC 的导航、最近与空白欢迎区形成三栏，文件名被挤窄，并重复新建入口。入口可用，但主要内容分散。
2. 编辑器：手机标题、视图与格式工具连续堆叠，工具栏没有清晰底色与分隔；系统蓝按钮和正文高亮过重。正文、保存及编辑预览入口可辨认，仍需验证重排后的焦点和横屏。
3. 设置：卡片和选项容器层层叠加，字号增减分散；主题和视图的按钮宽度不一，说明文字占据大量高度。设置分组可用，但不同控件缺少共同尺度。

截图保留在 build-logs/quality25-*-before.*。截图只能支持布局和视觉判断，不能据此声明无障碍合规或动画流畅。

## 设计和实现边界

采用纸色背景、墨色文字与低饱和蓝绿色强调；明暗主题都同步原生页面、编辑器和 Markdown 预览。主操作使用实色，普通操作留白，选中项使用浅色底；统一 44vp 热区与 6vp 控件圆角。

PC 首页改为窄导航与宽文档区，最近列表成为主要内容；手机以标题和紧凑新建入口、成组文件入口、搜索及列表组织。编辑器将视图切换放入分段容器，格式工具使用独立工具条，正文与侧栏有清楚边界。设置采用平整分组、等宽选项及成组字号控件，保留帮助折叠。

复用 AppTheme、ControlStyle 和现有页面组件，不建立新主题框架。删除被新结构替代的欢迎面板空白和收起列表状态。只改展示和组件组合，不改保存、删除、拖入、授权与偏好格式。

验证计划：宿主回归、SDK 单测、HAP 构建；手机与 PC 新截图对照同尺寸旧截图，检查浅深色、设置生效、菜单与正文焦点；用任务文件验证保存及删除，保留原有文档。记录未测场景后提交推送。回退本提交即可恢复旧界面，不涉及数据迁移。
