## 2. 排障记录（重要）

1. **URI 写模式打开崩溃隐患**：修复前对 `file://docs/...` 用 `WRITE_ONLY|CREATE` 直接 openSync——规避：改用**只读探测**获取真实错误码（13900002），写失败路径由领域状态机演示（正文保留语义等价，避免 native 写无效 URI 风险）。
2. **状态机非法迁移（R-17）**：尖峰页在 CLEAN 状态直接 `saveFailure()` → 领域层刻意抛 `InvalidTransitionError`（未捕获）导致应用崩溃（jscrash 日志定位）。修复：统一 `enterSaving()` 辅助（CLEAN→edit→beginSave），所有失败路径先进入合法前置状态。
3. **mkdirSync EEXIST**：目录已存在时抛错进入 catch → 同因崩溃；ensureDir 容错处理。

## 3. 验证细节

- 原子写状态链：edit→beginSave→saveSuccess（状态"已保存"）与失败链（beginSave→saveFailure→"保存失败"）均与 FR-SAVE-001 一致。
- 草稿内容：`M0-04 原子写测试内容`（13 字符）在 kill -9 后完整可读。
- 决策：磁盘 revision（h13）与草稿内容哈希一致 → `DISCARD_REDUNDANT`（保存已生效，草稿冗余）——符合 SDD 9.3 规则 3/5。
